# EPUB 基本格式渲染：需求与开发计划

状态：已确认，待实现

目标版本：v0.2（建议）

最后更新：2026-06-27

## 1. 背景

YATER 当前在解析 EPUB 章节时，将 XHTML 块转换为扁平的 `TextBlock`、`ImageBlock`。`TextBlock` 只保存规范化后的纯文本和注释锚点；粗体、斜体、标题、列表等语义会在解析时丢失。渲染阶段只会叠加当前句高亮和注释标记样式。

本功能要在不引入浏览器级排版引擎的前提下，保留 EPUB 中最常见、在终端里有稳定表达方式的格式。

## 2. 目标

1. 读者能够在 TUI 中辨认正文的强调、标题、引用和列表结构。
2. 格式渲染与当前句高亮、注释标记、自动换行和 typewriter 居中行为正确组合。
3. 保持现有扁平 `Vec<Block>`、句子字节偏移、注释字节偏移和阅读进度模型可用。
4. 不支持的 XHTML/CSS 必须退化为可读纯文本，不得导致章节解析或渲染失败。
5. 解析结果与终端能力无关；终端不支持某个修饰符时只降低视觉效果，不影响正文内容和导航。

## 3. 非目标

首版不尝试复刻 EPUB 在浏览器中的像素级布局，也不实现以下能力：

- 完整 CSS 解析、选择器匹配、层叠、继承和媒体查询。
- 外部样式表、内嵌 `<style>` 和 `style` 属性驱动的格式。
- 字体、字号、行高、字距、页边距、浮动、绝对定位和分页。
- 前景色、背景色和作者主题。当前句的紫色前景必须始终清晰可见。
- 表格、数学公式、SVG 文本排版、ruby 注音和竖排。
- 上标、下标的几何定位；终端没有可靠的基线位移能力。
- 超链接激活、复制链接或跨章节锚点跳转。
- 注释浮窗正文的富文本渲染。注释继续使用现有纯文本模型。

CSS 子集应在语义标签版本通过真实 EPUB 语料验证后单独立项，避免首版同时引入 DOM 样式语义和 CSS 层叠两类风险。

## 4. 首版范围

### 4.1 格式映射

| EPUB/XHTML 来源 | TUI 表现 | 数据语义 | 优先级 |
| --- | --- | --- | --- |
| `<strong>`、`<b>` | 粗体 | `BOLD` | 必须 |
| `<em>`、`<i>` | 斜体 | `ITALIC` | 必须 |
| `<u>`、`<ins>` | 下划线 | `UNDERLINED` | 必须 |
| `<s>`、`<strike>`、`<del>` | 删除线 | `CROSSED_OUT` | 必须 |
| `<h1>` | 粗体 + 下划线，块前后留一空行 | `role = Heading(1)` | 必须 |
| `<h2>`–`<h6>` | 粗体，块前后留一空行 | `role = Heading(level)` | 必须 |
| `<blockquote>` | 每个可见行使用暗色 `│ ` 前缀 | `quote_depth` | 必须 |
| `<ul>/<li>` | `• ` 前缀；嵌套层级增加缩进 | `list_item = Bullet(depth)` | 必须 |
| `<ol>/<li>` | `1. `、`2. ` 等前缀；读取 `start` | `list_item = Ordered(depth, ordinal)` | 必须 |
| `<br>` | 强制换行 | 保持现有行为 | 必须 |
| `<p>`、`<div>` | 独立文本块 | `Paragraph` | 保持现有行为 |
| `<img>` | 独立图片块 | `ImageBlock` | 保持现有行为 |

补充规则：

- `<b>` 和 `<i>` 按视觉兼容标签处理，不区分其与 `<strong>`、`<em>` 的语义差异。
- 未列出的内联标签只保留其可见文本，不附加样式。
- 样式可以嵌套。例如 `<strong><em>text</em></strong>` 同时渲染为粗体和斜体。
- 列表项中包含多个段落时，第一个段落显示项目符号，后续段落按同级悬挂缩进显示。
- 嵌套列表仍被压平为阅读顺序中的多个 `TextBlock`，不把 `Document` 改回 DOM 树。
- 空标题、空列表项和只包含空白的格式范围不生成空 `TextBlock`。

### 4.2 样式合成优先级

同一段文本可能同时具有 EPUB 格式和 YATER 运行时状态。渲染器按以下规则组合，而不是相互覆盖：

1. EPUB 基础格式提供粗体、斜体、下划线和删除线等修饰符。
2. 当前句高亮只设置前景色 `#a97df4`，保留 EPUB 修饰符。
3. 注释标记额外增加粗体和下划线，保留 EPUB 修饰符及当前句前景色。
4. 引用边线、列表符号和缩进属于块装饰，不计入正文文本，也不改变句子或注释的字节偏移。

示例：当前句中的 `<em>[1]</em>` 注释标记应同时具有紫色、斜体、粗体和下划线。

### 4.3 文本与偏移不变量

格式功能不得改变正文的逻辑文本：

- `TextBlock.text` 继续保存 UTF-8 字符串；句子范围、样式范围和注释位置都使用该字符串的字节偏移。
- 解析前后的空白规范化规则保持一致，`<br>` 继续产生显式换行。
- 所有样式范围必须位于文本范围内，起止位置必须是 UTF-8 字符边界，且不能为空。
- 规范化后相邻且样式完全相同的范围应合并。
- 嵌套标签在解析阶段展平为互不重叠、按起点排序的有效样式范围；渲染器不依赖原始 DOM。
- 块装饰产生的前缀和空行仅存在于渲染布局中，不写入 `TextBlock.text`，避免破坏保存的阅读位置。

## 5. 用户故事

1. 作为读者，我希望 EPUB 中的粗体和斜体在终端中仍可辨认，以便理解作者的强调。
2. 作为读者，我希望章节内标题与普通段落有清晰区别，以便快速识别内容层级。
3. 作为读者，我希望引用和有序/无序列表保留结构，以免内容被压成难以理解的连续段落。
4. 作为使用句子导航的读者，我希望当前句高亮不遮盖原有格式。
5. 作为使用脚注的读者，我希望注释标记样式与 EPUB 格式正确叠加。
6. 作为使用兼容性较差 EPUB 的读者，我希望未知格式退化为纯文本，而不是无法打开整本书。

## 6. 验收标准

### 6.1 解析

- 给定包含各个首版标签的最小 EPUB，解析结果的纯文本与当前规范化结果一致。
- 每个内联格式生成正确的字节范围和样式标志。
- 嵌套、相邻和跨句子的格式范围能正确展平、合并和截断。
- 样式标签包住注释链接时，样式范围和 `AnnotationRef.offset` 指向同一份规范化文本。
- 标题、引用和嵌套列表产生正确的块类型、层级和序号。
- 未知标签、空标签和格式错误但仍可解析的内容退化为纯文本。

### 6.2 渲染

- `ratatui::backend::TestBackend` 中的目标单元格带有预期 `Modifier`。
- 当前句在带格式文本中仍使用紫色前景，且保留原有修饰符。
- 注释标记继续为粗体 + 下划线，并能与斜体、删除线等格式组合。
- 标题空行、引用边线、列表前缀和悬挂缩进在窄终端换行后仍然对齐。
- 块装饰不影响 `j/k` 句子导航、`h/l` 块导航、章节跳转或进度恢复。
- TOC 获得焦点时仍移除当前句高亮，但保留 EPUB 自身格式。

### 6.3 兼容性与回归

- 现有单元测试、运行时 UI 测试和 EPUB 语料测试全部通过。
- 不含格式标签的 EPUB，其解析文本、块数量和渲染结果保持不变。
- 图片前后的格式范围不能跨越 `ImageBlock`。
- 终端尺寸变化后，当前句仍能根据带块前缀的实际行宽保持在 typewriter 中心区域。
- 不支持某种终端修饰符时正文仍然完整可读，不输出原始 XHTML 标签。

## 7. 技术设计

### 7.1 数据模型

建议扩展 `TextBlock`，而不是新增富文本树：

```rust
pub struct TextBlock {
    pub text: String,
    pub chapter_index: usize,
    pub annotations: Vec<AnnotationRef>,
    pub presentation: TextBlockPresentation,
    pub styles: Vec<TextStyleRange>,
}

pub struct TextBlockPresentation {
    pub role: TextBlockRole,
    pub quote_depth: usize,
    pub list_item: Option<ListItemPresentation>,
}

pub struct TextStyleRange {
    pub start: usize,
    pub end: usize,
    pub style: TextStyle,
}

pub struct TextStyle {
    pub bold: bool,
    pub italic: bool,
    pub underlined: bool,
    pub crossed_out: bool,
}
```

`TextBlockRole` 至少包含 `Paragraph` 和 `Heading(level)`；`ListItemPresentation` 保存无序/有序类型、嵌套深度、序号以及是否为同一列表项的续段。引用深度、列表上下文和内容角色必须可以组合，例如“引用中的二级有序列表项”，因此不建议把它们做成互斥的单一枚举。实际实现可以采用其他紧凑表示，但必须维持上述可观察语义。

选择字节范围而不是 `Vec<StyledTextRun>` 的原因：

- 句子和注释已经使用同一文本上的字节偏移。
- 纯文本仍可直接用于分句、进度恢复和搜索等未来功能。
- 运行时只需对句子边界、样式边界和注释边界做一次合并切分。
- 保持 ADR-0001 的扁平块模型，不让渲染和导航重新依赖 DOM 树。

该模型确认后，应补充 ADR-0002，记录“扁平块 + 样式字节范围”决策。

### 7.2 解析流程

解析器遍历可见 XHTML 时维护当前样式栈和列表/引用上下文：

1. 进入受支持的内联标签时，合并当前样式并记录开始位置。
2. 收集文本、图片和注释锚点，沿用现有块切分逻辑。
3. 离开标签时记录原始文本上的样式事件。
4. `flush_text_block` 在一次空白规范化过程中，同时重映射注释位置和样式边界。
5. 将样式事件扫描为排序、互不重叠的有效样式范围。
6. 图片或嵌套块触发 flush 时，关闭当前输出段的范围；后续文本根据仍在栈中的样式重新开始范围。

空白规范化必须只有一个实现入口，不能分别规范化文本、注释和样式，否则偏移迟早会漂移。

### 7.3 渲染流程

当前渲染器按句子和注释标记切分 `Span`。建议改为统一边界扫描：

1. 收集当前块内的句子、EPUB 样式和注释标记边界。
2. 排序并去重所有边界。
3. 对每个相邻区间计算基础格式、当前句状态和注释标记状态。
4. 合成一个 `ratatui::style::Style` 并输出 `Span`。
5. 块级渲染器再添加空行、引用边线、列表前缀和悬挂缩进。

块前缀会改变可用换行宽度，内容行高和当前句行号缓存的 key 必须纳入块类型、缩进或最终可用宽度，避免复用错误缓存。

## 8. 测试策略

项目继续执行严格的 Red-Green-Refactor：每个生产代码改动必须由失败测试驱动。

### 8.1 解析器测试

- 为每种标签添加最小 EPUB 测试。
- 使用包含 CJK、emoji 和组合修饰符的文本验证 UTF-8 边界。
- 覆盖嵌套样式、相邻样式、跨 `<br>`、图片切块、注释链接和空白规范化。
- 覆盖有序列表 `start`、嵌套列表和列表项多段落。

### 8.2 渲染器测试

- 直接检查 `TestBackend` 单元格的 `fg` 和 `Modifier`，不只断言屏幕文本。
- 使用窄宽度覆盖引用、列表的自动换行和悬挂缩进。
- 覆盖 EPUB 格式、当前句、注释标记三层样式组合。
- 覆盖 TOC 焦点和窗口 resize 后的行号缓存。

### 8.3 集成与语料测试

- 新增一个可提交的小型合成 EPUB fixture，避免核心格式测试依赖被忽略的大型语料。
- 继续运行可选的真实 EPUB corpus，检查无 panic、无非法范围和块数量异常。
- 运行 `cargo fmt --check`、`cargo test --locked`、`cargo check --locked` 和 `git diff --check`。

## 9. 开发阶段

### 阶段 0：确认与基线

- 确认本文件中的标签矩阵、CSS 非目标和标题/列表的终端表现。
- 记录现有无格式 EPUB 的解析与 UI 回归基线。
- 在实现前创建 ADR-0002。

完成条件：需求被确认，未决项清零，基线测试通过。

### 阶段 1：数据模型与不变量

- 用失败测试定义 `TextStyleRange`、`TextBlockPresentation` 及其合法性。
- 扩展测试构造器，避免所有测试重复填写默认字段。
- 暂不改变用户可见渲染。

完成条件：现有行为不变，新模型可表达首版全部格式。

### 阶段 2：内联格式解析

- 先实现粗体和斜体，再实现下划线和删除线。
- 将空白规范化、注释偏移和样式偏移统一映射。
- 覆盖嵌套标签、图片切块、`<br>` 和 Unicode。

完成条件：解析器输出稳定、规范化的样式范围，纯文本无回归。

### 阶段 3：内联格式渲染

- 实现统一边界扫描和样式合成。
- 处理当前句高亮及注释标记的叠加。
- 更新行号计算与缓存测试。

完成条件：四类内联格式及三层样式组合在 `TestBackend` 中通过。

### 阶段 4：块级格式

- 依次实现标题、引用、无序列表和有序列表。
- 实现窄终端中的换行、悬挂缩进和 typewriter 定位。
- 覆盖嵌套列表和列表项多段落。

完成条件：块级验收标准全部通过，导航和进度行为无回归。

### 阶段 5：集成与文档收尾

- 运行完整测试矩阵和真实 EPUB 语料。
- 更新 `CONTEXT.md`、`README.md`、`docs/PRD_v1.md` 中已变化的行为描述。
- 将本文件状态改为“已实现”，记录已知终端差异和后续 CSS 兼容项。

完成条件：所有检查通过，文档与实现一致。

## 10. 风险与控制

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 空白规范化导致样式和注释偏移漂移 | 错误文本被着色，甚至 UTF-8 切片 panic | 单次规范化同时重映射全部边界；增加 Unicode 属性测试样例 |
| Span 切分逻辑分别处理多种状态 | 组合样式丢失或优先级不一致 | 使用统一边界扫描和单一样式合成函数 |
| 列表/引用前缀改变实际换行宽度 | 当前句无法居中或滚动跳动 | 行高计算与绘制共享同一块布局函数 |
| 标题/列表引入大量空 Block | 导航粒度异常 | 块装饰不进入正文文本；空节点不生成 Block |
| 真实 EPUB 主要依赖 CSS class | 首版格式覆盖率有限 | 明示语义标签范围；通过 corpus 统计后设计 CSS 子集 |
| 终端不支持斜体或删除线 | 视觉区分退化 | 保持纯文本完整；不以终端支持作为解析条件 |

## 11. 已确认决策

以下产品决策已于 2026-06-27 确认，作为实现基线：

1. **CSS 范围**：首版只识别 XHTML 语义标签，不解析任何 CSS。
2. **标题表现**：`h1` 使用粗体 + 下划线，`h2`–`h6` 使用粗体，全部前后留一空行。
3. **引用表现**：使用暗色 `│ ` 边线，不强制斜体。
4. **列表表现**：支持嵌套和有序列表 `start`，前缀只参与布局、不进入正文。
5. **注释富文本**：首版继续以纯文本展示注释。

任何新增格式应先更新范围和验收标准，再进入 TDD 实现。
